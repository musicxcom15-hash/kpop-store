# คู่มือทดสอบเว็บ KPOP STORE ผ่าน VS Code

เว็บนี้เป็น **HTML static ล้วน** เก็บข้อมูลทั้งหมดไว้ใน `localStorage` ของเบราว์เซอร์
ไม่มีฐานข้อมูลจริง ดังนั้นทดสอบได้ทันทีโดยไม่ต้องติดตั้งอะไรเลย

---

## 1. วิธีเริ่มทดสอบ (เลือกอย่างใดอย่างหนึ่ง)

### วิธี A — Live Server (แนะนำ ง่ายและเร็วที่สุด)

1. เปิดโฟลเดอร์ `D:\ProjectPreorder` ใน VS Code
2. คลิกปุ่ม **Go Live** ที่แถบสถานะมุมล่างขวา
3. เบราว์เซอร์จะเปิดที่ `http://127.0.0.1:5500/` เอง

> ✅ ไม่ต้อง `npm install` เลย
> ✅ **แก้ไฟล์แล้วกด Ctrl+S หน้าเว็บจะรีเฟรชเองอัตโนมัติ**

หรือคลิกขวาที่ไฟล์ `preorderkpopweb/order-history.html` → **Open with Live Server**

### วิธี B — กด F5 (ได้ debugger ตั้ง breakpoint ด้วย)

1. กด **Go Live** ให้ Live Server ทำงานก่อน (ตามวิธี A)
2. กด **F5** → เลือก **🌐 ทดสอบหน้าประวัติการสั่งซื้อ (Live Server)**
3. Chrome จะเปิดขึ้นมาพร้อมต่อ debugger ให้อัตโนมัติ

### วิธี C — express server (ตรงกับตอน deploy จริงที่สุด)

```
npm install     # ครั้งแรกครั้งเดียว (ตอนนี้ยังไม่มี node_modules)
npm start
```

แล้วเปิด `http://localhost:3000/order-history.html`
หรือกด **F5** → เลือก **🚀 express server + เปิดเบราว์เซอร์อัตโนมัติ**

## 2. ⚠️ กับดักที่ต้องรู้ก่อนทดสอบ

**`127.0.0.1:5500` กับ `localhost:3000` เป็นคนละ origin → `localStorage` แยกกันคนละชุด**

ถ้าคุณทดสอบสั่งซื้อไว้ที่พอร์ต 5500 แล้วสลับไปเปิดพอร์ต 3000 ออเดอร์จะ "หายไป"
**นี่ไม่ใช่บัค** แต่เป็นพฤติกรรมปกติของเบราว์เซอร์ — เลือกใช้พอร์ตเดียวตลอดการทดสอบจะสับสนน้อยที่สุด

(`127.0.0.1` กับ `localhost` ก็นับเป็นคนละ origin เช่นกัน แม้จะพอร์ตเดียวกัน)

## 3. รีเซ็ตข้อมูลกลับเป็นค่าตั้งต้น

เปิด DevTools (กด **F12**) → แท็บ **Console** → วางคำสั่งนี้แล้ว Enter:

```js
['kpop_products','kpop_users','kpop_orders','kpop_notifications',
 'kpop_current_user','kpop_cart','kpop_rounds','kpop_rates']
  .forEach(k => localStorage.removeItem(k)); location.reload();
```

> ⚠️ `kpop_rounds` และ `kpop_rates` เป็นคีย์ใหม่ ถ้าลืมล้างสองตัวนี้ รอบและเรทจากรอบทดสอบก่อนจะค้างอยู่
> ทำให้ราคาสินค้าและสถานะรอบไม่ตรงกับที่คู่มือบอก แล้วหาสาเหตุไม่เจอ

ข้อมูลจะกลับไปเป็นชุด demo ตั้งต้น (สินค้า 4 รายการ, ลูกค้า 2 คน, ออเดอร์ 3 รายการ,
รอบพรีออเดอร์ 3 รอบ, เรทตั้งต้น 0.0265 บาท/วอน)

**ควรรีเซ็ตก่อนเริ่มทดสอบทุกครั้ง** ไม่อย่างนั้นสถานะออเดอร์จากรอบก่อนจะค้างและทำให้ผลทดสอบเพี้ยน

## 4. บัญชีสำหรับทดสอบ

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| ผู้ดูแลระบบ | `admin@kpopstore.com` | `admin123` |
| ลูกค้า (สมชาย) | `user@kpopstore.com` | `123456` |
| ลูกค้า (โซมี) | `somi@kpopstore.com` | `123456` |

> ⚠️ **เปลี่ยนไปจากเวอร์ชันก่อน — ข้อพวกนี้ทำให้ผลทดสอบต่างจากที่เคยจำไว้**
>
> 1. **ข้อมูลอยู่ใน MySQL แล้ว ไม่ใช่ `localStorage`** ต้องเปิด MAMP และ import
>    `database/kpop_store.sql` ก่อน ไม่งั้นหน้าเว็บจะขึ้นว่าติดต่อเซิร์ฟเวอร์ไม่ได้
>    ผลพลอยได้: เปิดคนละเบราว์เซอร์/คนละเครื่องแล้วเห็นข้อมูลชุดเดียวกัน
> 2. **รหัสผ่านถูกตรวจจริงทุกบัญชี** ด้วย `password_verify()` — กรอกรหัสผิดเข้าไม่ได้
>    และ **อีเมลที่ยังไม่สมัครจะไม่ถูกสร้างบัญชีให้อัตโนมัติอีกแล้ว**
> 3. **เปิดเว็บครั้งแรกจะยังไม่ล็อกอิน** ต้องกดเข้าสู่ระบบเองก่อน
> 4. **หน้ารายละเอียดสินค้าดูได้โดยไม่ต้องล็อกอิน** กำแพงย้ายไปอยู่ที่ปุ่ม
>    "เพิ่มลงตะกร้า" และ "สั่งซื้อทันที" แทน
> 5. **ตะกร้าผูกกับบัญชี** ล็อกอินคนละบัญชีบนเครื่องเดียวกันจะเห็นตะกร้าคนละใบ
> 6. หน้าแอดมินไม่มีปุ่ม "เข้าสู่ระบบในฐานะแอดมินทันที" แล้ว (เดิมฮาร์ดโค้ดรหัสไว้)
>    ต้องล็อกอินด้วย `admin@kpopstore.com` ตามปกติ

## 4B. ทดสอบอัตโนมัติด้วย `npm test` (ทำก่อนไล่เช็กลิสต์มือ)

```
npm test
```

ต้องขึ้นว่า **ผ่านครบทั้ง 7 ไฟล์ รวม 254 เคส** ใช้เวลาไม่ถึง 1 วินาที
ไม่ต้อง `npm install` ก่อน เพราะชุดทดสอบใช้แต่ของที่มากับ Node อยู่แล้ว

**ต่างจากเช็กลิสต์ข้อ 5 ยังไง** — ข้อ 5 คือคนไล่กดเองในเบราว์เซอร์
ส่วน `npm test` คือเครื่องตรวจ **ตรรกะ** ให้เองโดยไม่ต้องเปิดเบราว์เซอร์
มันโหลด `preorderkpopweb/js/store.js` **ตัวจริง** เข้าไปรันใน localStorage จำลอง

> `store.js` เป็น data layer ล้วน ๆ (ไม่แตะ DOM) ส่วน navbar/modal/แถบล่างมือถือ
> ย้ายไปอยู่ `js/ui.js` แล้ว ซึ่งต้องโหลด **หลัง** `store.js` เสมอ —
> ถ้าหน้าไหนไม่มี navbar หรือปุ่มออกจากระบบหาย ให้เช็คก่อนว่าหน้านั้นมี
> `<script src="js/ui.js"></script>` ครบหรือเปล่า
โค้ดที่ถูกตรวจจึงเป็นไฟล์เดียวกับที่ลูกค้าใช้ ไม่ใช่ของจำลอง

> **ควรรัน `npm test` ทุกครั้งหลังแก้โค้ด** ถ้าแดงแปลว่าแก้แล้วพังของเดิม
> ให้ย้อนดูก่อนจะเสียเวลาไล่กดมือ — แต่ถ้าเขียว **ยังไม่ได้แปลว่าเว็บใช้งานได้**
> เพราะส่วนที่พึ่งหน้าจอจริง (เลย์เอาต์ · การอัปโหลดรูป · modal) ตรวจใน Node ไม่ได้
> จึงต้องไล่เช็กลิสต์ข้อ 5 กับ 5B ต่อเสมอ

| ไฟล์ | ตรวจเรื่องอะไร | จำนวนเคส |
|---|---|---|
| `tests/order-status.test.mjs` | ตาราง 12 สถานะ · เปลี่ยนสถานะ · ล้างเลขพัสดุ · แจ้งเตือน | 39 |
| `tests/rounds-rates-quota.test.mjs` | รอบ · เรทเงินวอน · โควตา · ตะกร้า · OUT OF STOCK | 58 |
| `tests/refund-flow.test.mjs` | กดของไม่สำเร็จแล้วคืนเงิน | 28 |
| `tests/product-image.test.mjs` | อัปโหลดรูปสินค้า · พื้นที่เก็บข้อมูลเต็ม | 21 |
| `tests/delete-order.test.mjs` | ลบคำสั่งซื้อ · คืนโควตา | 23 |
| `tests/save-failure.test.mjs` | บันทึกไม่ลงต้องไม่บอกว่าสำเร็จ · ด่านส่งสลิปใบใหม่ | 28 |
| `tests/admin-product.test.mjs` | จัดการสินค้า/ผู้ใช้ฝั่งแอดมิน · กันอีเมลซ้ำ · สิทธิ์ | 57 |
| | **รวม** | **254** |

เวลาแก้บั๊กแล้วอยากดูเฉพาะไฟล์เดียว สั่งตรงได้เลย (รันจากโฟลเดอร์ไหนก็ได้):

```
node tests/delete-order.test.mjs
```

ผลจะขึ้นเป็นรายเคส `ok` หรือ `FAIL` พร้อมบอกว่าได้ค่าอะไรมาแทนที่ค่าที่ควรได้

> บรรทัด `Error writing localStorage key: ... QuotaExceededError` ที่โผล่ระหว่างรัน
> **ไม่ใช่เทสต์พัง** — เป็น log ของ `store.js` ตอนถูกทดสอบด้วยกรณีพื้นที่เต็มโดยตั้งใจ
> ดูบรรทัดสรุปท้ายสุดเป็นหลักว่า "ไม่ผ่าน" เป็น 0 หรือเปล่า

## 5. เช็กลิสต์ทดสอบบัคที่เพิ่งแก้ไป

เริ่มจาก **รีเซ็ตข้อมูล** (ข้อ 3) ก่อนเสมอ แล้วไล่ตามลำดับนี้

### ☐ 5.1 ยกเลิกออเดอร์แล้วต้องบันทึกจริง *(บัคหลัก)*

1. ล็อกอินด้วย `user@kpopstore.com`
2. ไปหน้า **ประวัติคำสั่งซื้อ** → หาออเดอร์ `ORD-2026071301` (NewJeans)
3. กดปุ่ม **ยกเลิก**

**ต้องเห็น:** กล่องยืนยัน → กล่องกรอกเหตุผล → ข้อความแจ้งว่ายกเลิกสำเร็จ →
การ์ดเปลี่ยนเป็นป้ายแดง "ยกเลิกคำสั่งซื้อโดยลูกค้า"

4. **กด F5 รีเฟรชหน้า**

**ต้องเห็น:** สถานะยังเป็น "ยกเลิก" อยู่
*(บัคเดิม: สถานะจะเด้งกลับเป็น "รอตรวจสอบชำระเงิน" เพราะบันทึกไม่ลง)*

5. ล็อกอินเป็นแอดมิน → แท็บ **จัดการสินค้า** → ดูคอลัมน์ "โควตารับ/รอบ" ของ NewJeans

**ต้องเห็น:** โควตาคงเหลือเพิ่มจาก **34 → 35** (คืนเข้ารอบแล้ว)
*(ให้จดตัวเลขไว้ก่อนกดยกเลิก แล้วเทียบว่าเพิ่มขึ้น 1 พอดี)*

> ระบบไม่ได้เก็บตัวนับ `stock` ไว้ในสินค้าอีกแล้ว แต่คำนวณโควตาคงเหลือสด ๆ
> จากออเดอร์ที่ยังไม่ถูกยกเลิกในรอบนั้น ตัวเลขจึงคืนเองทันทีที่สถานะเปลี่ยน

### ☐ 5.2 ป้ายสถานะ "จัดส่งสำเร็จ" ต้องเป็นสีเขียว

ล็อกอิน `somi@kpopstore.com` → ดูออเดอร์ `ORD-2026070102`

**ต้องเห็น:** ป้าย**เขียว** "จัดส่งสำเร็จเรียบร้อย" พร้อมไอคอนติ๊กถูก
*(บัคเดิม: ขึ้นป้ายฟ้า "กำลังจัดส่งพัสดุ" ทั้งที่ของถึงมือลูกค้าแล้ว)*

### ☐ 5.3 แท็บกรองสถานะ

กดครบทั้ง 5 แท็บ แล้วนับจำนวนออเดอร์

**ต้องเห็น:** ออเดอร์แต่ละรายการอยู่ในแท็บเดียวเท่านั้น และผลรวมของ 4 แท็บย่อย
ต้องเท่ากับจำนวนในแท็บ "คำสั่งซื้อทั้งหมด" พอดี (ไม่มีตกหล่น ไม่มีนับซ้ำ)

### ☐ 5.4 คนที่ยังไม่ล็อกอินต้องไม่เห็นข้อมูลลูกค้าคนอื่น

ใน Console พิมพ์:

```js
localStorage.setItem('kpop_current_user','null'); location.reload();
```

**ต้องเห็น:** การ์ด "กรุณาเข้าสู่ระบบก่อนดูประวัติคำสั่งซื้อ" และแท็บกรองถูกซ่อน
*(บัคเดิม: เห็นออเดอร์ของลูกค้าทุกคน พร้อมชื่อ เบอร์โทร ที่อยู่ และรูปสลิป)*

### ☐ 5.5 ออเดอร์ที่ยกเลิกเองห้ามส่งสลิปใหม่

1. เปิด **ดูรายละเอียด** ของออเดอร์ที่ยกเลิกไปในข้อ 5.1

**ต้องเห็น:** **ไม่มี**ช่องอัปโหลดสลิป แต่มีข้อความอธิบายว่าให้สั่งซื้อรายการใหม่แทน
*(บัคเดิม: อัปโหลดได้ ทำให้ออเดอร์ฟื้นกลับมาโดยไม่ตัดสต็อก → ของขายเกิน)*

2. เข้าหน้าแอดมิน → กดปฏิเสธสลิปของออเดอร์อื่น → กลับมาดูในหน้าลูกค้า

**ต้องเห็น:** ออเดอร์ที่ถูกแอดมินปฏิเสธ **ยังอัปโหลดสลิปใหม่ได้ตามปกติ**

### ☐ 5.6 เปิดรูปสลิปซ้อนบนหน้าต่างรายละเอียด

เปิด **ดูรายละเอียด** → คลิกที่รูปสลิป → กดปิดรูป

**ต้องเห็น:** ยังเลื่อน (scroll) หน้าต่างรายละเอียดที่อยู่ข้างหลังได้ตามปกติ
*(บัคเดิม: หน้าค้าง เลื่อนไม่ได้ ต้องปิดทั้งหมดแล้วเปิดใหม่)*

### ☐ 5.7 สั่งซื้อสินค้าใหม่ทั้ง flow

หน้าแรก → เลือกสินค้า → สั่งซื้อ → กรอกที่อยู่ → แนบสลิป → ยืนยัน

**ต้องเห็น:** สร้างออเดอร์สำเร็จ, ออเดอร์โผล่ในหน้าประวัติ, และสต็อกสินค้าลดลงตามจำนวนที่สั่ง
*(บัค `saveProducts` เดิมทำให้ขั้นตอนนี้พังด้วย)*

### ☐ 5.8 หน้าจอขนาดกลาง

อยู่ที่หน้า **ประวัติคำสั่งซื้อ** แล้วย่อหน้าต่างเบราว์เซอร์ให้เหลือกว้างประมาณ 800px

**ต้องเห็น:** เมนูด้านบน (หน้าแรก / สินค้าทั้งหมด / วิธีการสั่งซื้อ / ประวัติคำสั่งซื้อ) ยังอยู่ครบ
*(บัคเดิม: เมนูหายทั้งแถบในช่วง 768–991px)*

**ตอนนี้แก้ครบทุกหน้าแล้ว** — ให้ไล่ดูที่ความกว้าง **767 / 768 / 991 / 992px**
ทั้ง `index.html`, `login.html`, `register.html`, `product-detail.html`, `cart.html`
และ `order-history.html`

**ต้องเห็น:** ทุกความกว้างมีทางนำทางเสมออย่างน้อยหนึ่งอย่าง —
ต่ำกว่า 768px ใช้**แถบล่างมือถือ** ตั้งแต่ 768px ขึ้นไปใช้**เมนูบน**
*(สาเหตุบัคเดิม: แถบล่างซ่อนตัวที่ ≥768px แต่เมนูบนโผล่ที่ ≥992px
ช่วงระหว่างนั้นจึงไม่มีทั้งคู่ และไม่มีปุ่มแฮมเบอร์เกอร์ให้กดด้วย)*

### ☐ 5.9 ตรวจ Console

ตลอดการทดสอบทุกข้อ เปิด DevTools (F12) แท็บ **Console** ค้างไว้

**ต้องเห็น:** ไม่มีข้อความ error สีแดงเลย

## 5B. เช็คลิสต์ฟีเจอร์ใหม่ (รอบ / เรทเงินวอน / ตะกร้า / คืนเงิน)

รีเซ็ตข้อมูลก่อนเริ่ม (หัวข้อ 3) ทุกครั้ง

### ☐ 5B.1 ตะกร้าแยกตามรอบ และค่าส่งคิดแยก

1. หน้าแรก → เพิ่ม **BTS** ลงตะกร้า (อยู่รอบเว็บเกาหลี)
2. เพิ่ม **BLACKPINK** ลงตะกร้า (อยู่รอบหิ้วหน้าร้าน)
3. เปิดหน้า **ตะกร้า**

**ต้องเห็น:** แยกเป็น **2 กล่องตามรอบ** แต่ละกล่องมีปุ่มชำระเงินของตัวเอง
และเก็บค่าส่ง **กล่องละ ฿50** พร้อมข้อความอธิบายว่าของคนละรอบส่งพร้อมกันไม่ได้

### ☐ 5B.2 เช็คเอาต์รอบเดียว ต้องไม่ล้างตะกร้าทั้งใบ *(บั๊กที่เคยเกือบเกิด)*

ต่อจากข้อ 5B.1 → กด **ชำระเงินรอบนี้** ของกล่องแรก → แนบสลิป → ยืนยัน

**ต้องเห็น:** สร้างออเดอร์สำเร็จ แล้วกลับมาดูตะกร้า **BLACKPINK ของอีกรอบต้องยังอยู่**
*(ถ้าตะกร้าว่างเปล่าแปลว่าโค้ดเรียก `clearCart()` แทน `clearCartRound()`)*

### ☐ 5B.3 ราคาขยับตามเรท แต่ยอดที่จ่ายแล้วต้องนิ่ง

1. แอดมิน → แท็บ **เรทเงินวอน** → ตั้งเรท `0.0270` กด **มีผลทันที** → บันทึก
2. กลับหน้าลูกค้า จดราคา BTS ไว้ → ใส่ตะกร้า **ยังไม่จ่าย**
3. แอดมิน → ตั้งเรท `0.0350` มีผลทันที
4. กลับไปดูตะกร้า

**ต้องเห็น:** ราคา BTS ในตะกร้า**ขยับขึ้นเอง** และแบนเนอร์บอกเรทใหม่

5. กดชำระเงิน แนบสลิป ยืนยัน → เปิดหน้าประวัติ ดูรายละเอียดออเดอร์ จดยอดไว้
6. แอดมิน → ตั้งเรท `0.0200` มีผลทันที → กลับมาดูออเดอร์เดิม

**ต้องเห็น:** **ยอดในออเดอร์ไม่ขยับเลย** และในรายละเอียดระบุว่าใช้เรท `0.035` พร้อมเวลาที่ล็อก

### ☐ 5B.4 เรทเปลี่ยนระหว่างกรอกฟอร์ม ต้องเตือนก่อนบันทึก

1. เปิดหน้า checkout ค้างไว้ (ยังไม่กดยืนยัน)
2. เปิดแท็บใหม่ → แอดมิน → ตั้งเรทใหม่ มีผลทันที
3. กลับไปแท็บ checkout → แนบสลิป → กด **ยืนยัน**

**ต้องเห็น:** กล่องแจ้งว่าเรทเปลี่ยน พร้อมยอดเดิมกับยอดใหม่ และ**ยังไม่บันทึกออเดอร์**
ต้องกดยืนยันอีกครั้งถึงจะสั่งซื้อสำเร็จ

### ☐ 5B.5 รอบที่ปิดแล้วต้องสั่งไม่ได้ทุกทาง

แอดมิน → แท็บ **จัดการรอบพรีออเดอร์** → แก้รอบเว็บเกาหลีให้ **วันปิดรับเป็นเมื่อวาน** → บันทึก

**ต้องเห็น:** ในตารางรอบขึ้นสถานะ **"ปิดรับแล้ว"** และฝั่งลูกค้า:
หน้าแรกการ์ด BTS จาง + ป้าย "ปิดรับรอบนี้แล้ว" · หน้ารายละเอียดปุ่มสั่งซื้อถูกปิด ·
ในตะกร้ากล่องรอบนั้นกดชำระเงินไม่ได้

### ☐ 5B.6 โควตาคืนเองเมื่อแอดมินปฏิเสธสลิป *(บั๊กเดิมค้างถาวร)*

1. แอดมิน → แท็บสินค้า → แก้ NewJeans ตั้ง **โควตารับต่อรอบ = 3** → บันทึก
2. สั่งซื้อ NewJeans จนครบ 3 ชิ้น

**ต้องเห็น:** สินค้าขึ้น "เต็มโควตารอบนี้" สั่งเพิ่มไม่ได้

3. แอดมิน → แท็บ **ตรวจสอบสลิป** → กด **ปฏิเสธ** ออเดอร์นั้น

**ต้องเห็น:** โควตา**กลับมาทันที** ลูกค้าสั่งซื้อได้อีก
*(บัคเดิม: โควตาค้างที่ 0 ตลอดไป ของขายไม่ได้ทั้งที่ไม่มีใครจ่ายเงิน)*

### ☐ 5B.7 ใบสรุปรอบสำหรับเอาไปกดของ

แอดมิน → แท็บ **จัดการรอบพรีออเดอร์** → กดปุ่มไอคอนคลิปบอร์ดของรอบที่มีออเดอร์

**ต้องเห็น:** ตารางรวมจำนวนต่อสินค้า (เช่น BTS 7 ชิ้น) พร้อมยอดวอนที่ต้องจ่าย
และยอดบาทที่รับจากลูกค้า — ใช้ถือไปกดสั่งที่เว็บเกาหลีได้เลยโดยไม่ต้องบวกเลขเอง

### ☐ 5B.8 กดของไม่สำเร็จ → คืนเงิน

1. แอดมิน → แท็บคำสั่งซื้อ → กด **ปรับสถานะ** ออเดอร์ที่ชำระแล้ว
2. กดปุ่ม **กดของไม่สำเร็จ → รอคืนเงิน** → ใส่เหตุผล → ยืนยัน

**ต้องเห็น:** ป้ายสถานะเป็น**สีเหลือง** (ไม่ใช่แดงแบบ "ถูกปฏิเสธ") ·
โควตาคืนเข้ารอบ · **ยอดขายรวมในแดชบอร์ดลดลง** · ลูกค้าได้การแจ้งเตือน

3. ฝั่งลูกค้า → หน้าประวัติ → กดแท็บ **คืนเงิน**

**ต้องเห็น:** ออเดอร์อยู่ในแท็บนี้ **ไม่ใช่แท็บ "จัดส่งแล้ว"**
*(ข้อความสถานะมีคำว่า "สำเร็จ" อยู่ ระบบเดิมที่เดาจากข้อความจะจับผิดกลุ่ม)*

4. กลับไปที่แอดมิน กด **คืนเงินให้ลูกค้าแล้ว**

**ต้องเห็น:** สถานะเป็น "คืนเงินเรียบร้อยแล้ว" และลูกค้าได้แจ้งเตือนอีกครั้ง

### ☐ 5B.9 ยกเลิกไม่ได้หลังร้านจ่ายเงินให้เกาหลีแล้ว

แอดมิน → ปรับสถานะออเดอร์เป็น **"ร้านกดสั่งกับเกาหลีแล้ว"** → กลับไปหน้าลูกค้า

**ต้องเห็น:** **ปุ่มยกเลิกหายไป** ทั้งในการ์ดและในหน้าต่างรายละเอียด
*(ถ้ายังยกเลิกได้ ร้านจะเสียเงินจริงเพราะจ่ายให้เกาหลีไปแล้ว)*

### ☐ 5B.10 อัปโหลดรูปสินค้า

แอดมิน → แท็บ **จัดการสินค้า** → **เพิ่มสินค้าใหม่**

1. กด **อัปโหลดจากเครื่อง** เลือกไฟล์รูป

**ต้องเห็น:** preview ขึ้นทันที พร้อมข้อความบอกขนาดหลังย่อ (เช่น "ประมาณ 72 KB")

2. กรอกข้อมูลที่เหลือแล้วบันทึก → **กด F5 รีเฟรช**

**ต้องเห็น:** รูปยังอยู่ทั้งในตารางสินค้า หน้าแรก หน้ารายละเอียด และในตะกร้า

3. แก้ไขสินค้าเดิมที่ใช้ URL (เช่น BLACKPINK ที่ใช้ลิงก์ Unsplash)

**ต้องเห็น:** ช่อง URL มีลิงก์เดิม และ preview แสดงรูปถูกต้อง

4. อัปโหลดไฟล์ทับสินค้าตัวนั้น → **ไฟล์ที่เลือกต้องชนะ URL เดิม**
5. กด **ลบรูป** → กลับไปใช้รูปสำรอง **ไม่ใช่รูปแตก**
6. ลองเลือกไฟล์ที่ไม่ใช่รูป (เช่น .txt เปลี่ยนนามสกุลเป็น .jpg)

**ต้องเห็น:** ข้อความบอกว่าอ่านไฟล์ไม่สำเร็จ ไม่ใช่เงียบหายหรือบันทึกรูปเสีย

7. ลองไฟล์ใหญ่ ๆ (5-10 MB) → ต้องถูกย่อเหลือหลักสิบ KB และหน้าไม่ค้าง

### ☐ 5B.11 พื้นที่เต็มต้องไม่บอกว่าบันทึกสำเร็จ *(เคสสำคัญที่สุดของฟีเจอร์รูป)*

ดูแถบ **พื้นที่เก็บข้อมูลในเบราว์เซอร์** ที่หัวแท็บจัดการสินค้า — บอก % ที่ใช้ไป
(เหลืองเมื่อเกิน 70% แดงเมื่อเกิน 90%)

ทดสอบตอนเต็มจริง: เปิด Console แล้วถมพื้นที่จนเกือบเต็ม

```js
try { let s = 'x'.repeat(1024 * 1024);
      for (let i = 0; i < 10; i++) localStorage.setItem('kpop_filler' + i, s); }
catch (e) { console.log('เต็มแล้ว:', e.name); }
```

จากนั้นลองอัปโหลดรูปสินค้าแล้วกดบันทึก

**ต้องเห็น:** ข้อความ **"บันทึกไม่สำเร็จค่ะ"** พร้อมคำแนะนำให้ใช้ URL หรือลบข้อมูลเก่า
*(บัคเดิมก่อนแก้: `setJSON` กลืน error เงียบ ๆ ทำให้ขึ้นว่า "บันทึกเรียบร้อยแล้วค่ะ!"
ทั้งที่ข้อมูลไม่ได้ลง แล้วรูปหายตอนรีเฟรชโดยไม่มีอะไรบอกสาเหตุ)*

ล้าง filler ทิ้งเมื่อทดสอบเสร็จ:

```js
Object.keys(localStorage).filter(k => k.startsWith('kpop_filler'))
  .forEach(k => localStorage.removeItem(k));
```

### ☐ 5B.12 ลบคำสั่งซื้อ (คืนพื้นที่เก็บข้อมูล)

แอดมิน → แท็บ **คำสั่งซื้อทั้งหมด** → กดปุ่มถังขยะ

1. ลบออเดอร์ที่ **จบกระบวนการแล้ว** (จัดส่งสำเร็จ / ยกเลิก / คืนเงินแล้ว)

**ต้องเห็น:** กล่องยืนยันแสดงเลขที่ ชื่อลูกค้า ยอดเงิน สถานะ
พร้อมข้อความว่าการลบจะคืนพื้นที่ · กดยืนยันแล้วออเดอร์หายจากตาราง
และ**แถบพื้นที่เก็บข้อมูลลดลง**

2. ลบออเดอร์ที่ **ยังไม่จบ** (เช่น "รอตรวจสอบชำระเงิน" หรือ "ร้านกดสั่งกับเกาหลีแล้ว")

**ต้องเห็น:** กล่องยืนยันขึ้น **⚠️ คำเตือนที่แรงกว่า** ว่าลูกค้าจ่ายเงินแล้วและยังรออยู่
พร้อมแนะให้ใช้ "ปรับสถานะ" แทนถ้าตั้งใจจะยกเลิก/คืนเงิน

3. จดโควตาคงเหลือของสินค้าในออเดอร์นั้นไว้ก่อน แล้วลบออเดอร์

**ต้องเห็น:** **โควตาคืนเข้ารอบทันที** โดยไม่ต้องกดอะไรเพิ่ม
(เพราะโควตาคำนวณสดจากออเดอร์ที่เหลืออยู่)

4. ตรวจว่าทุกส่วนอัปเดตตาม: ยอดขายรวมในแดชบอร์ด · แท็บตรวจสอบสลิป ·
   ใบสรุปรอบในแท็บจัดการรอบ · ตารางสินค้า

5. ล็อกอินเป็นลูกค้าเจ้าของออเดอร์นั้น → หน้าประวัติ

**ต้องเห็น:** ออเดอร์หายไปจากประวัติของลูกค้าด้วย (เป็นการลบถาวร ไม่ใช่ซ่อน)

### ☐ 5B.13 ลบสินค้าที่ยังมีออเดอร์ค้าง ต้องถูกบล็อก

แอดมิน → แท็บ **จัดการสินค้า** → กดถังขยะที่ **BTS** (มี `ORD-2026062815` สถานะ "กำลังจัดเตรียมสินค้า")

**ต้องเห็น:** กดยืนยันแล้วขึ้นกล่องว่า **ลบไม่ได้** พร้อมบอกจำนวนใบและเลขที่ `ORD-2026062815`
และแนะให้เปลี่ยนป้ายเป็น OUT OF STOCK แทน · **สินค้าต้องยังอยู่ในตาราง**
*(บัคเดิม: ลบผ่านเงียบ ๆ แล้วโควตาเพี้ยนเป็น 0 ราคากลายเป็น ฿0)*

จากนั้นลอง **BLACKPINK** (มีแต่ออเดอร์ที่จัดส่งสำเร็จแล้ว)

**ต้องเห็น:** ลบได้ตามปกติ ขึ้นว่าลบเรียบร้อย และแถบพื้นที่เก็บข้อมูลอัปเดต
(ใบที่ส่งถึงมือลูกค้าแล้วไม่นับว่า "ค้าง")

### ☐ 5B.14 เตือนก่อนย้ายรอบ / ก่อนตั้งโควตาต่ำกว่ายอดจอง

1. แก้ไข **BTS** → เปลี่ยน **รอบพรีออเดอร์** เป็นรอบอื่น → กดบันทึก

**ต้องเห็น:** กล่อง confirm เตือนว่าออเดอร์ที่ค้างอยู่จะไม่ถูกนับในโควตารอบใหม่ ·
กด **ยกเลิก** แล้วข้อมูลต้องไม่เปลี่ยน

2. แก้ไข **BTS** → ตั้ง **โควตารับต่อรอบ** เป็น `1` (จองไปแล้ว 2) → กดบันทึก

**ต้องเห็น:** กล่อง confirm บอกว่าจองไปแล้ว 2 ชิ้น · ถ้ากดตกลง
คอลัมน์โควตาต้องขึ้นป้ายแดง **"เกินโควตา"** พร้อมบรรทัด "จองแล้ว 2 / เพดาน 1 ชิ้น"
*(บัคเดิม: ขึ้นแค่ "เหลือ 0 / 1" ซึ่งดูเหมือนขายพอดีเป๊ะ)*

### ☐ 5B.15 ชื่อสินค้าที่มีอักขระพิเศษต้องไม่ทำหน้าเพี้ยน

เพิ่มสินค้าใหม่ ตั้งชื่ออัลบั้มเป็น `Girls" <b>Test</b> & Co`

**ต้องเห็น:** ตารางแสดงข้อความ**ตรงตัวทั้งหมด** ไม่มีตัวหนา ไม่มีช่องเพี้ยน
และปุ่มแก้ไข/ลบของแถวนั้นยังกดทำงานได้ปกติ

**ตรวจให้ครบทุกที่ที่ชื่อไปโผล่** (รอบนี้เพิ่งไล่ escape ให้ครบทั้งระบบ):
แดชบอร์ด · ตารางคำสั่งซื้อ · ตารางรอบ · ตารางเรท · ตารางผู้ใช้ · หน้าแรก ·
และกระดิ่งแจ้งเตือนบน navbar

ทดสอบให้หนักกว่านั้นได้โดยตั้ง**ชื่อลูกค้า**ตอนสมัครสมาชิกเป็น
`<img src=x onerror=alert(1)>` แล้วสั่งซื้อ 1 ใบ จากนั้นเข้าหน้าแอดมินไล่ดูทุกแท็บ
**ต้องไม่มีกล่อง alert เด้งขึ้นมาเลยแม้แต่ครั้งเดียว**

5. ล็อกอินด้วย `user@kpopstore.com`
6. **ต้องเห็น:** เด้งกลับมาที่**หน้ารายละเอียดของสินค้าตัวที่กดไว้** ไม่ใช่หน้าแรก

ทดสอบเส้นทางเช็คเอาต์ด้วย: ล็อกอินแล้วใส่ของลงตะกร้า → ออกจากระบบ → เปิด `cart.html`
→ กด "ชำระเงินรอบนี้" → ต้องเด้งไป login แล้วกลับมาที่หน้า checkout เดิมพร้อมรายการครบ

---

### ☐ 5B.17 ป้าย OUT OF STOCK ต้องหยุดขายจริง

1. เข้าแอดมิน → แท็บสินค้า → แก้สินค้าใบใดใบหนึ่ง → เปลี่ยนป้ายสถานะเป็น **หมดชั่วคราว**
2. **ต้องเห็นในหน้าแรก:** การ์ดจาง ๆ พร้อมป้าย "หมดชั่วคราว" และปุ่มเป็น "ดูรายละเอียด"
3. เปิดหน้ารายละเอียดสินค้านั้น → **ปุ่มเพิ่มลงตะกร้าและสั่งซื้อทันทีต้องถูกปิด**
   พร้อมข้อความ "สินค้าหมดชั่วคราว"
4. ลองเปิด `checkout.html?id=<id ของสินค้านั้น>&qty=1` ตรง ๆ จาก URL
   → **ปุ่มยืนยันต้องถูกปิดเช่นกัน** (ด่านไม่ได้อยู่แค่ที่ปุ่มบนหน้าจอ)

---

### ☐ 5B.18 ส่งสลิปใบใหม่ตอนรอบปิดแล้ว ต้องถูกปฏิเสธ

1. สั่งซื้อ 1 ใบ → เข้าแอดมิน → **ปฏิเสธสลิป**
2. เข้าแอดมิน → แท็บรอบ → แก้รอบของสินค้านั้นให้สถานะเป็น **ปิดรับแล้ว**
3. กลับไปหน้าประวัติคำสั่งซื้อของลูกค้า → เปิดรายละเอียด → แนบสลิปใบใหม่ → กดส่ง
4. **ต้องเห็น:** ข้อความบอกว่ารอบปิดรับแล้ว ส่งไม่ได้ และ**สถานะยังเป็น "ยกเลิก/สลิปไม่ผ่าน"**
   (ก่อนแก้ ระบบจะรับสลิปกลับเข้ามาเป็น "รอตรวจสลิป" แล้วกินโควตาของรอบที่ปิดไปแล้ว)

---

### ☐ 5B.19 สมัครสมาชิกด้วยอีเมลซ้ำ ต้องยึดบัญชีคนอื่นไม่ได้

1. ไปหน้าสมัครสมาชิก กรอกอีเมล `admin@kpopstore.com` แล้วกดสมัคร
2. **ต้องเห็น:** ข้อความบอกว่าอีเมลนี้มีบัญชีอยู่แล้ว และถูกพาไปหน้าเข้าสู่ระบบ
3. ล็อกอินด้วย `admin@kpopstore.com` / `admin123` → **ต้องยังเข้าหน้าแอดมินได้ตามปกติ**
   และชื่อยังเป็น "ผู้ดูแลระบบ (Admin)" ไม่ถูกเขียนทับด้วยชื่อที่เพิ่งกรอก
4. ลองสมัครด้วยอีเมลแปลก ๆ ที่มีคำว่า admin เช่น `myadmin@test.com`
   → สมัครได้ปกติ แต่**ต้องเป็นลูกค้าธรรมดา** เข้า `admin.html` ไม่ได้

## 6. การตั้ง breakpoint (เวลาเจอบัคแล้วอยากรู้ว่าพังตรงไหน)

1. เปิดไฟล์ `preorderkpopweb/js/store.js`
2. คลิกที่ช่องว่างซ้ายมือของเลขบรรทัดที่สนใจ (เช่น ในฟังก์ชัน `cancelOrderCustomer`) → จะมีจุดแดงขึ้น
3. กด **F5** เลือก config **🌐 ทดสอบหน้าประวัติการสั่งซื้อ**
4. ไปกดปุ่มในหน้าเว็บที่เรียกโค้ดตรงนั้น → VS Code จะหยุดที่บรรทัดนั้นทันที
5. ดูค่าตัวแปรได้ที่แผง **Variables** ด้านซ้าย หรือเอาเมาส์ชี้ที่ชื่อตัวแปรในโค้ด
6. ปุ่มควบคุม: **F10** ข้ามทีละบรรทัด, **F11** เข้าไปในฟังก์ชัน, **F5** ทำงานต่อ

ตั้ง breakpoint ในโค้ด `<script>` ที่อยู่ในไฟล์ `order-history.html` ได้เหมือนกัน

## 7. จุดที่ควรส่องใน DevTools

| แท็บ | ดูอะไร |
|---|---|
| **Console** | error สีแดง (ถ้ามีแปลว่าโค้ดพัง) |
| **Application → Local Storage** | คีย์ `kpop_orders` — เช็ค `statusCode`, `roundId`, `rateUsed` ว่าบันทึกลงจริงไหม |

| **Elements** | ตรวจ HTML ที่ JS สร้างขึ้นมาจริงๆ |
